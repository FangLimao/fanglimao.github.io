或许，你已经尝试过 Minecraft 中一些知名的模组，比如暮色森林、魔法金属、农夫乐事等。

<!-- more -->

不论这些模组内容多么纷繁复杂，但是它们都有一个共同的特点：**都对游戏内容进行了修改，并在其之上添加了更多原版游戏没有的内容**——而对这些第三方内容的包容，也是 Minecraft 风靡至今的原因之一。

那这一切，又与附加包有什么关系呢？附加包又是什么呢？

## 什么是附加包？

附加包是什么？关于这个问题，Mojang 在一篇文章中做过说明：

> 对于新手来说，附加包基本上是一组文件，可以让改变游戏世界的运作方式。
> 想要 50 英尺高的鸡？当然可以！想要创建一支穿着蓬蓬裙的猪灵大军？虽然很怪，但是也可以！
> 
> ——[Michael Ott, Add-Ons: What's in a name?](https://www.minecraft.net/zh-hans/article/add-ons-whats-name)

而关于这个问题，Minecraft Wiki 是这么论述的：

> **附加包（Add-on）** 允许玩家更改世界的纹理样貌、实体的模型、行为规则等，是实现 Minecraft 全版本自定义的坚实一步。
> 
> ——[附加包 - 中文 Minecraft Wiki](https://zh.minecraft.wiki/附加包)，采用[CC BY-NC-SA 3.0](https://creativecommons.org/licenses/by-nc-sa/3.0/)授权

简而言之，附加包与 Java 版中的模组类似，都可以对 Minecraft 进行一系列的更改，不同的是附加包是基岩版中独有的，而且附加包的修改方式与模组不同，它依赖于数据驱动与 Script API。

> 数据驱动是什么？ Script API 又是什么？听起来要长脑子了……
> 
> 在这里，我们先不深究，后面会详细讲解。

如果没有特殊声明，本小册中的**模组**均指依赖 NeoForged、Fabric 等第三方模组加载器对游戏进行修改的方式，而**附加包**均指基岩版中依赖数据驱动与 Script API 对游戏实现修改的方式。

## 附加包能干什么？

在现代版本中，附加包对游戏进行自定义的能力已经迎头赶了上来：我们可以用附加包创建自定义的物品、实体、方块等，也可以添加自己的战利品表、配方，亦或是利用脚本对游戏事件进行监听！

然而由于诸多原因，附加包对游戏的自定义能力相较于模组还**有很大的缺陷**，例如：附加包无法添加新的维度，没有对游戏内 UI 进行自定义的成熟方法，一些硬编码的物品、方块也无法通过附加包进行修改……**我们要对此做好心理准备。**

## 「数据驱动」

简单来说，基于一些数据驱动游戏内容的方式叫做**数据驱动（Data-Driven）**。

在具体操作中，游戏允许我们按照一定的格式编写配置文件，然后游戏会根据这些配置文件，对原版的对应的游戏内容进行修改。

> 尽管数据驱动允许我们修改一些原版内容，然而正如导论中所提到的，目前大部分原版的物品、方块都是硬编码的，我们无法对其进行修改。
> 如果真的要对一些原版内容进行修改，请考虑一下附加包间的兼容性。
>
> 举个例子，如果我们修改原版的`player.json`来尝试更改玩家的行为时，如果其他行为包也修改了`player.json`，那么就会导致冲突，导致一些不可预料的错误.

而配置文件使用的格式，就是 JSON。

## 行为与资源

附加包通常分为资源包和行为包，两者可以访问对方的资源，它们一般一起运行，但有时也可以独立运行而不出错。

**资源包（Resource Pack）**，通常缩写为 **RP** 或 **RES**，其通常包括：

- 纹理；
- 模型；
- 动画；
- 粒子音效。

**行为包（Behavior Pack）**，通常缩写为 **BP** 或 **BEH**，其通常包括:

- 方块文件；
- 物品文件；
- 实体文件；
- 脚本文件；
- 配方、战利品表文件。

行为包和资源包的资产一般而言是可以互相访问的，例如，想要创建一个自定义物品，我们就需要在行为包定义它的行为（如它的 ID 是什么，最大堆叠是多少，可不可以食用……），再在资源包中定义它的纹理、名称等。

正因如此，**在大多数情况下**，想要完整实现游戏内容，需要行为包和资源包同时工作才可以做到。
